## Executive Summary

Added an inline email capture section to the landing page to capture visitors who engage with the hero but don't immediately click through to `/chefs`. This creates a second capture point alongside `/subscribe`, intercepting users who want to stay informed but aren't ready to book.

```
Second Entry Point:

    → Only visitors explicitly looking for waitlist reach this page
```

**Problem:** The landing page has no mid-funnel capture mechanism. Visitors who engage with the hero but don't convert are lost.

---

## Growth Idea: Inline Waitlist Capture

### Rationale

Adding an inline "Stay Updated" callout on the landing page captures visitors who:
- Saw the hero, found it interesting, but aren't ready to book
- Want to return when the platform is more mature
- Would convert at launch if reminded

This is a "reminder + anticipation" mechanism, not a hard sell.

### Design

Insert between the Hero and "How It Works" sections — a warm, low-commitment prompt:

```
┌─────────────────────────────────────────────────────────┐
│  Stay in the Loop                                       │
│  Get early access updates and chef announcements       │
│  [________________________] [Notify Me]                 │
│  47 food lovers already waiting                         │
└─────────────────────────────────────────────────────────┘
```

### Implementation

**File:** `src/components/WaitlistCapture.tsx` (new)

- Client-side component with inline form
- Submit to existing `/api/subscribe` endpoint (no backend changes needed)
- Shows success state after submission (no page redirect)
- Shows "already subscribed" gracefully if email exists
- Reuses the same design language as `SubscribeForm.tsx` but simplified

**File:** `src/app/page.tsx` (modified)
- Import `WaitlistCapture` component
- Insert between Hero and "How It Works" sections
